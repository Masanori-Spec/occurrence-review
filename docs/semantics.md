# Comparison semantics and design

## Input contract

Both inputs represent complete current-state snapshots. Absence on one side means absence from that snapshot, so do not compare a full calendar against a filtered export or scheduling delta. VERSION:2.0 and exactly one balanced VCALENDAR are required. PRODID and DTSTAMP are not required by this scoped tool; therefore acceptance is not a claim of full RFC validity. LF and CRLF and folded lines are accepted. Date lexical forms must be compact RFC 5545 forms with seconds; numeric offsets and leap seconds are rejected.

The strict preflight catches forms which ical.js may normalize permissively (zero INTERVAL, junk after dates/numbers, duplicate RRULE parts, unbalanced components). Semantic validation then reads parsed properties. A syntax failure invalidates the whole snapshot. A known-UID semantic failure blocks that UID on both sides while other valid UIDs may still be compared. An unidentifiable event blocks the whole comparison. Diagnostic truncation is visible.

## Recurrence subset

Pinned ical.js 2.2.1 parses ICS; this application does **not** call its unbounded recurrence iterator. The supported subset is generated by a calendar-day scan with a global step budget. UTC arithmetic is used only as an arithmetic coordinate system for date/floating values; they do not become UTC instants.

Supported parts:

| Frequency | Supported selection |
| --- | --- |
| DAILY | INTERVAL; nonnumbered BYDAY; BYMONTHDAY; BYMONTH |
| WEEKLY | INTERVAL; nonnumbered BYDAY; BYMONTH; WKST |
| MONTHLY | INTERVAL; BYMONTHDAY; BYDAY (plain or ordinal ±1…5); BYMONTH |
| YEARLY | INTERVAL; BYMONTH; BYMONTHDAY |

COUNT or UNTIL (not both) is supported for each. COUNT counts selected valid candidates from DTSTART, including occurrences before the review window; EXDATE exclusion occurs after the count. UNTIL is inclusive and must match DTSTART's temporal type. DTSTART must satisfy the rule, because RFC 5545 leaves an unsynchronized DTSTART recurrence set undefined. UNTIL before DTSTART is rejected. Invalid dates (monthly 31st, yearly leap day) are skipped and do not consume COUNT.

Unspecified weekly weekday and monthly day derive from DTSTART. YEARLY without BYMONTH/BYMONTHDAY derives its month and day from DTSTART. With BYMONTHDAY and no BYMONTH, days expand across every month of the selected year. YEARLY BYDAY is deliberately unsupported, as are BYSETPOS, BYYEARDAY, BYWEEKNO, BYHOUR, BYMINUTE, BYSECOND, subdaily frequencies and extensions. WEEKLY BYMONTHDAY is invalid.

This is a small independently testable subset, not an alternative general-purpose recurrence engine. Test golden data uses Python dateutil as an independent implementation, with explicit examples from RFC 5545; neither dependency is treated as infallible.

## Identity and membership

A nonrecurring occurrence key is the UID plus `single`. A recurring key is UID plus original temporal type and recurrence-origin DATE/DATE-TIME. Detached DTSTART changes do not change the key. IDs are JSON-encoded tuples, preventing delimiter collision. No title similarity, nearest-date pairing, or sequence guessing is used.

The set is DTSTART ∪ RRULE ∪ RDATE, deduplicated by typed value; EXDATE wins. An override must match a member of that base set. Two overrides for one identity, or an override without a recurring master, are incomplete. An EXDATE still excludes that identity even if a detached override exists. For interoperability, producers should not use contradictory override/exclusion representations.

Each detached VEVENT is a replacement instance. Its duration and selected metadata come from that component, without field-by-field inheritance from the master. A missing end on a DATE-TIME instance means zero duration; on DATE, one day. Producers that intend to preserve fields must include them in the detached replacement. Cancelled overrides may omit DTSTART; a cancelled master may omit DTSTART. A cancelled series has no occurrences, and its detached instances cannot revive it.

We expand through the review end and explicit original identities / RDATE targets from both snapshots. Detached origins later than the review end are therefore validated and their moved-in occurrences discovered. If the old identity is beyond the step budget, the series is incomplete, never guessed. Opposite-side nonrecurring DTSTART targets keep outside-window counterparts available. The output is ordered by UID and key, not input order or machine locale date formatting.

## Changes and evidence

The result includes added / removed / changed occurrences. A changed occurrence can have several flags:

- `start`: start value changed within the same temporal domain (a verified move)
- `duration`: effective duration changed, independently of start
- `metadata`: one or more selected fields changed

Metadata properties are normalized for property ordering, sorted parameters and repeated property order. Categories/resources values are sorted within each property. Text, escaping, parameters and values remain significant. This is not a semantic equality engine for arbitrary URIs or attendee addresses. Raw metadata before/after values are included in evidence; the UI renders them as inert text.

Bookkeeping timestamps, SEQUENCE, VALARM, ATTACH and X-properties are intentionally ignored, as are calendar-level metadata and fields outside the selected list. Every report declares that scope. Recurrence rule changes with identical bounded occurrence effect produce no occurrence changes; this tool does not claim the rules themselves are unchanged.

## Timezone decision

Every referenced TZID is unsupported. Embedded VTIMEZONE components with no references can be ignored, but they never register global definitions. Identically named differing timezones in before/after cannot contaminate each other. Spring gaps, autumn folds, unknown TZID and embedded timezone definitions are tested as explicitly incomplete. Do not remove TZID just to make a report complete: doing so changes the meaning of the data.

## Report and operational contract

`complete` is the authoritative gate. Summary categories can overlap. At a row/byte cap, summary change counts include only emitted rows. At report-wide overflow, detailed rows and counts are discarded and a clear output-limit diagnostic remains. `unchanged` counts only compared occurrences in scope, not blocked UIDs. No wall-clock timestamp or runtime duration is included in JSON, preserving reproducibility.

JavaScript entry point:

```js
import { compareCalendars } from './src/engine.js';
const report = compareCalendars(beforeIcs, afterIcs, {
  start: '2026-01-01', end: '2026-02-01',
  limits: { maxSteps: 50000 }
});
```

Limits may only be reduced; `maxReportBytes` has a 16 KiB minimum. Invalid options throw; malformed/unsupported calendars return an incomplete report. The shipped CLI and browser isolate the synchronous engine in a worker and apply independent timeouts.
